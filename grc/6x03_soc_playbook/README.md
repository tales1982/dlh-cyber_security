# 6x03: The SOC Playbook

SOC automation for MedDefense, built after the incident in which one IP lookup took 45 minutes while the attacker moved to two more hosts. It contains an IOC enrichment engine, a SQLite case manager and two playbooks (phishing triage and credential exposure) that enrich, classify and create cases automatically, and stop at a human checkpoint before any response action.

- **Organization:** MedDefense (fictional training scenario, DLH Academy)
- **Author:** Tales Lima
- **Date:** 2026-11-18

## Deliverables

| Task | File | Content |
| --- | --- | --- |
| 1 | [enrich_ioc.py](enrich_ioc.py) | IOC type detection, IP classification (including documentation ranges), reverse DNS, feed lookup, scoring; module and CLI (single and batch) |
| 2 | [case_manager.py](case_manager.py) | SQLite case store (`cases`, `case_notes`, `case_iocs`), daily case IDs, notes, status, close; CLI `list`, `get`, `close`, `note` |
| 3 | [playbook_phishing_triage.py](playbook_phishing_triage.py) | Extracts and deduplicates sender IP, sender domain and URL hosts; ESCALATE / REVIEW / CLOSE ladder; case and audit line |
| 4 | [playbook_credential_exposure.py](playbook_credential_exposure.py) | Enriches source IP, checks Domain Admin / Server Admin, applies the decision table, writes the isolation queue for analyst authorization; ATT&CK names |
| 4 | [privileged_accounts.json](privileged_accounts.json) | Privileged account inventory used by the credential playbook (copy of the provided file) |
| 5 | [integration_test_results.md](integration_test_results.md) | Five scenarios with command, verbatim stdout, case record, expected vs actual (5 of 5 PASS), defects found and fixed |

Generated by the integration run (kept as evidence, do not delete):

- [cases.db](cases.db): the five cases created by the test.
- [playbook_audit.log](playbook_audit.log): one line per playbook execution.
- [isolation_queue.json](isolation_queue.json): one host (`WST-WS-031`) pending analyst authorization.

Inputs: [ioc_feed.json](ioc_feed.json) (local threat intel feed), [alerts/](alerts/) (the six provided alert fixtures) and [materials/](materials/) (the provided lab materials, unchanged).

## Usage

```bash
# Enrichment
python3 enrich_ioc.py 198.51.100.42
python3 enrich_ioc.py --batch iocs.txt --output results.json

# Playbooks
python3 playbook_phishing_triage.py alerts/ALT-20260428-001.json
python3 playbook_credential_exposure.py alerts/ALT-20260428-007.json

# Cases
python3 case_manager.py list                     # every status except closed
python3 case_manager.py list --status escalated  # or open, investigating, closed, all
python3 case_manager.py get CASE-20261118-001
python3 case_manager.py close CASE-20261118-002 "benign; confirmed newsletter sender"
```

Python 3.8+, standard library only. No call leaves the host except reverse DNS, which returns `NXDOMAIN` or `TIMEOUT` (3 seconds) when no resolver answers, so the scripts run without internet access. Files (`ioc_feed.json`, `privileged_accounts.json`, `cases.db`, `playbook_audit.log`, `isolation_queue.json`) are read and written in the current directory.

## Automation Boundary

| Automated | Not automated (needs an analyst) |
| --- | --- |
| IOC enrichment and scoring | Blocking a sender or IP |
| Case creation, severity and notes | Mailbox quarantine |
| Escalation to the on-call analyst | Host isolation: the playbook only writes `isolation_queue.json` with `status: pending_authorization` |
| Closing phishing alerts whose IOCs are all internal or allowlisted (lab only; needs a measured false-negative rate before production) | Account disablement |

## Re-running the Integration Test

Follow `materials/integration/integration_test_checklist.md`. Its first step deletes `cases.db`, `playbook_audit.log` and `isolation_queue.json`, so copy them elsewhere first if the current evidence must be kept.
